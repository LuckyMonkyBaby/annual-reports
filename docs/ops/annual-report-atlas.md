# Annual Report Atlas

The application is a static cover gallery with a butter-yellow (`#f4e18c`) and vermilion (`#9a241c`) theme that reverses with the system color preference. The default entry briefly shows an authored two-color “Annual reports” cover, filling the entire viewport on desktop and mobile, including navigation and the header, then automatically folds it from the bottom-right corner into Goldman Sachs 2024 as an enlarged featured cover with twelve color matches; `?view=all` opens the full gallery. A compact navigation header links the two entry views and follows the outer rendered cover edges, and the footer uses only an oversized wordmark. The original PDF link appears whenever a cover is selected; the reset button appears only in the full gallery. Search and All reports share the right cover edge, with the clear icon reserved to the left of the search field, and reset/search-clear use the official inline Lucide X SVG with its license in `dist/lucide-license.txt`. Browsing supports: search company/ticker/year, click a cover, animate into twelve nearest color matches, and open its original PDF from the top-left toolbar. Search reuses matching mounted cards, reserves clear-button space, freezes toolbar insets while the field is focused, and reserves scrollbar space so typing does not move the caret or reload unchanged covers. Ctrl+F / Cmd+F opens the application search, selects the current query; slash also focuses search. No framework, runtime server, account database, or browser persistence is required. Public image assets and `reports.json` live in `dist`; Vercel serves the static output. `dist/app.mjs` owns browsing and matching; `scripts/import_reports.py` owns discovery, issuer checks, PDF validation and first-page extraction. `scripts/color.py` owns palette extraction. No scheduled importer is configured.

## Approved palette

“Butter / Vermilion” is the current palette selected on October 5, 2026: butter `#f4e18c`, vermilion `#9a241c`. Light mode uses butter as the paper and vermilion as the ink; dark mode reverses them. The runtime tokens remain owned by `dist/style.css`. “Acid / Plum” remains saved as an alternative: `#e1f57b` / `#39233d`, with its implementation preserved in commit `d319ebd`. [Palette studies](../design/palettes.html) compare ten pairs against real gallery covers and default to the selected Butter / Vermilion; they are design studies, not a production palette switcher.

## Source boundary

The collection targets published reporting years 2020–2026 across current S&P 500 tracking-fund issuers. All available quarterly SEC indices are inspected, then missing company-years are attempted against AnnualReports.com archive PDFs. Successful PDF signatures and first-page images are verified; missing, rejected and failed reports remain explicitly recorded in `scripts/coverage.json`. Discovery uses the SEC quarterly master index and ARS filing detail pages, including attached PDFs when the primary document is HTML. PDF signatures are validated before Poppler extracts page one. Company CIKs are limited to equity holdings in iShares IVV, a maintained S&P 500 tracking fund. This is a membership proxy rather than a licensed official S&P constituent list; the downloaded holdings date and source are stored in `scripts/universe.json` and `reports.json`. Index membership is the inclusion boundary, including foreign-incorporated index members. SEC incorporation metadata is retained when available. The archive is incomplete where no accessible designed PDF is found. The selection uses current membership, not membership at the report date.

`year` uses the first-page annual-report title when available, otherwise the SEC reporting-period year. Both `yearBasis` and the original `period`/`filed` dates remain in the data. This avoids labeling a 2024 report as 2025 simply because its fiscal year ends in January 2025.

On desktop the selected cover spans two columns and two grid rows, scrolls naturally, and returns to four columns beneath it. On mobile it occupies the full gallery width above the matches. Clicking the selected cover, the toolbar reset, or Escape restores browsing. Toolbar edges follow the first row’s rendered cover bounds on load and resize; narrow mobile rows keep enough space for the controls. Captions use the rendered image width and an inset; the custom search clear button replaces the native browser icon. The enlarged desktop cover height follows the two standard cover rows, their 40px gap and 28px caption, aligning its bottom with the second related row. Cover images retain intrinsic proportions, so snapshots animate the actual image rather than a letterboxed frame. Native transitions use 300ms movement with an ease-out curve and 120ms fades, with a short sideways sheet reveal between views. Expanding a cover adds a left-edge hinge: its snapshot tilts 12 degrees in perspective with a temporary soft shadow, then settles flat within the same 300ms. Only the selected cover receives this book-opening motion; original PDF links remain direct. Unsupported pseudo-element animation falls back to the normal expansion. The clicked image is moved into the expanded card so its decoded bitmap survives; new related-image downloads do not block the transition. The intro waits at most 180ms for the priority cover image before opening over 2.4 seconds on desktop / 1.8 seconds on mobile. A live clipped cover and reflected SVG underside draw the bottom-right corner diagonally toward the top-left on desktop; mobile keeps the earlier leftward turn. The underside bends continuously between the crease and corner. A vector lighting gradient shades the bend without a raster blur, the reverse stays plain, and the crease line stays faint. A quintic easing curve starts and ends with zero velocity and acceleration. Wheel, touch, pointer, keyboard or resize input dismisses the decorative overlay immediately. The opening sheet fills the viewport, so the gallery and header become visible only where the fold uncovers them; no separate early fade reveals the underlying page. The gallery renders underneath without a network wait; known aspect ratios are reused to prevent caption/mobile layout shifts. Reduced-motion preferences disable transitions and hover fading.

## Image filtering and similarity

WebP decoding samples the rendered first page on a 32×32 grid. HSV pixels provide a coarse dominant hue while ignoring white margins; neutral covers fall back to grayscale. Plain pages with SEC commission and Form 10-K/Q headings and less than 8% chromatic content are excluded. Local Tesseract OCR checks uncertain monochrome pages because embedded PDF character maps can produce unreadable text; dense monochrome text pages are excluded too. This caught the user-reported Chipotle and Tapestry form pages while preserving the minimal Amazon cover. Monochrome designed covers without those form headings are preserved. This is a heuristic, not a model or aesthetic judgment; a designed SEC-form page may be excluded, while another plain text page may pass. Inspect new covers when growing the collection.

Nearest colors use squared RGB distance between dominant sampled colors, exclude the selected cover, and break ties by stable report ID. Matching is relative to this small collection; it does not infer layout or subject similarity.

## Operate

Requires Python 3, curl, Poppler (`pdftoppm`, `pdftotext`), WebP (`cwebp`, `dwebp`) and Tesseract OCR. Set `SEC_USER_AGENT` to an identifiable application and contact email if changing the operator; current contact was supplied by the user. The bulk importer uses four workers with a shared five-requests/second gate, retries transient failures twice, does not retry 404/410, and stays below SEC's documented 10 requests/second ceiling. Processed record metadata, first-page text and optional OCR output are cached outside Git in the OS temporary directory. Source PDFs are discarded after each report is processed; at most the active worker downloads are retained. Re-running resumes downloaded reports; delete the holdings/SEC ticker cache files to refresh membership.

```sh
python3 scripts/import_archive.py --start 2020 --end 2026
python3 scripts/build_gallery.py
node scripts/check.mjs
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

The bulk import resumes through processed-record caches and deduplicates company/report-year pairs, preferring the latest SEC filing; archive records fill gaps after SEC processing. Each successful record has a real PDF URL, CIK, tickers, cover image, palette and source provenance. SEC records retain accession/file dates; archive records use null for dates and filing/form metadata that were not obtained. The importer atomically replaces the JSON manifest as it progresses; keep a running import local until complete. Failures are explicitly recorded rather than claimed as imported. Before archive backfill the importer probes a known PDF; connection failures block the batch and are recorded in `archiveStatus`, distinct from a missing or rejected document. On October 5 the SEC pass completed, while local downloads from AnnualReports.com failed with curl connection errors; the older-year backfill remains incomplete and can resume when connectivity returns. Source PDFs may become unavailable upstream; local first-page images remain readable, while original-document links depend on SEC availability. Remove a record and its cover and republish to withdraw it. There is no scheduled updater; this bulk run is user-authorized manual expansion.

The browser check uses the parent workspace's installed Playwright, verifies image decoding, search/empty states, the PDF link, similar-cover navigation, Escape dismissal and mobile overflow, and records the actual UI outside Git. It requires the local server above. New checkouts need Playwright available to run that optional UI check; the product itself has no npm dependencies.

## Cost and speed

Page-one covers are rasterized once to 900-pixel JPEG intermediates in the temporary cache, then encoded once to quality-76 WebP files. Only WebP covers enter `dist`; full source PDFs are transient and intermediates remain outside Git. Vercel serves static files with no server functions, database or runtime image transformations. Immutable cover URLs include stable accession/source identifiers. When changing image encoding settings, generate a new filename/version to avoid stale browser caches. The first ten covers compressed from 997,039 to 527,202 bytes (47% reduction).

The browser renders 48 cards initially, appends more near the viewport with IntersectionObserver, and lazy-loads images. A bounded 800-pixel lookahead upgrades nearby images to eager loading and decodes them before they enter the viewport; new batches append 1200 pixels ahead so that buffer stays populated. CSS content-visibility:auto skips offscreen layout and paint while preserving the DOM and keyboard navigation. This is browser rendering virtualization, not a bounded DOM window; older batches remain mounted as the user scrolls. Search and palette comparisons run locally over the compact report manifest. CDN bandwidth and requests still count toward Vercel usage; caching does not make delivery free. Move the cover objects to separate object storage only if corpus size or measured traffic makes static deployment/transfer an actual constraint. The flat record manifest remains portable; UI cover URLs can be changed to a CDN without changing the source-PDF links.

## First paint and caching

After changing the corpus, app, stylesheet or page markup, run `python3 scripts/build_gallery.py`. It derives `catalog.json` from the reviewed `reports.json`, strips import-only metadata, reads intrinsic WebP dimensions and embeds 13 featured / 48 initial records into HTML. It also writes content-hashed copies of the source app/styles and updates their HTML references; deploy the generated output with source files. The first cover is preloaded at high priority from the HTML head before the module runs. Initial rendering needs no data request; the complete catalog fills in during idle time at low fetch priority. Matching cards and the selected image are reused when the catalog arrives. The compact catalog is 449,474 bytes versus 889,272 for the complete provenance manifest in the current corpus; initial HTML is about 22KB uncompressed. Original-source metadata remains in `reports.json` and coverage remains outside the runtime data boundary.

Code/style hashes and covers cache immutably for a year. Catalog data caches for five minutes with stale-while-revalidate; after an update, a returning client may see older membership for that cache window. HTML retains Vercel revalidation behavior and points at new hashes when code changes. Pure CSS `prefers-color-scheme` and theme-color metadata apply system dark mode before JS; artwork is never inverted. Reduced-motion users bypass the intro and book/sheet movement. Supported same-origin navigation uses native view transitions; unsupported browsers use normal navigation.
